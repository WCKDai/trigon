# FBX rendering exchange

`export.fbx` writes binary FBX for rendering applications using an optional, separately installed
Blender. All building geometry is generated by Trigon's Rust model. Trigon writes its embedded
GLB, then runs an original adapter through Blender's public Python API as a separate program.
Blender and its implementation code are not linked into Trigon. No account or paid service is
needed for this export; GLB and IFC remain available without Blender.

```sh
trigon run --doc model.trigon export.fbx '{"path":"out/model.fbx"}'
```

The command shares `phase`, `filter`, `cut_level` and `cut_mm` with `export.gltf`. It preserves
the document, dirty state, journal and Undo history. An installed `blender` on PATH is used;
the standard macOS application path is also recognised. The operator may set `TRIGON_BLENDER`
to an executable path in their environment. A document/command cannot supply executable paths
or converter scripts.

The adapter uses a private temporary directory, a fixed script, direct argument arrays, a
restricted child environment and `--disable-autoexec`/`--factory-startup`. API keys, control tokens
and Python startup variables are not forwarded. It runs headless with three CPU threads, and
has a 120-second limit. Missing tools, conversion failures and failed verification preserve any
existing destination. Only a successfully verified binary FBX replaces the final file atomically.

GLB nodes include the complete source ID in `extras.trigon_id`; this survives application object
name limits. FBX carries it as a custom property. Before accepting the export, the converter
reimports a copy in a fresh temporary folder and checks source-ID multiplicities, triangle counts,
UV availability, textured materials and actual texture pixels. Every element's vertex set must
match in both directions within **0.1 mm**. Images must be embedded or extracted within that fresh
folder, proving the FBX does not depend on the converter's previous texture files.

Trigon's site-local mm become metres in GLB. FBX carries explicit unit and axis metadata; the
round-trip check uses Blender's Z-up world coordinates in metres. Keep the `.trigon` file for
parametric edits. Use `.blend`, GLB or FBX in the rendering workflow. FBX does not encode the
complete Trigon BIM command history or a guarantee of identical PBR shader behaviour in another
renderer. Glass and material settings should be inspected in the target rendering application.

Run the original offline exchange fixture, including IDs longer than Blender's object-name limit:

```sh
CARGO_TARGET_DIR="$PWD/target" CARGO_BUILD_JOBS=3 cargo run --locked -p trigon-engine \
  --example fbx-workflow -- out/fbx-workflow
```

The [Blender public FBX export operator documentation](https://docs.blender.org/api/5.0/bpy.ops.export_scene.html)
defines the conversion options. Lumion lists FBX among its [supported import formats](https://lumion.com/news/lumion-2024-3-update).
Actual Lumion import and rendering are separate target-application checks; local Blender
verification alone does not establish their result.
